# Free-Tree non-split B-tree cost and test inventory

Scope: read-only source/test audit at `ec6bcb6`; no builds or runtime checks. This is supporting evidence, not an optimization proposal or acceptance decision.

The supplied current measurement reports 353/142/197 Free-Tree node writes for create / 8 MiB write / delete. It also reports zero Free-Tree split and two-edit-coalescence hits, and zero Free-Tree write/path-counter values for read workloads. Those zeros do not mean zero B-tree or BIO reads: each `node_read` calls `bfs_bio_read` (`src/core/btree.c:79-95`), and the allocator contains repeated searches/scans below. Aggregate write counts do not identify which B-tree operations generated them or whether a path guard was eligible. The structural-validation cache can avoid repeating CRC/order checks, but does not avoid loading the block into the caller's buffer.

## Current primitive work

### COW and node I/O

`node_write` stamps the node header, canonicalizes unused bytes, computes the node CRC and performs one `bfs_bio_write_node` (`src/core/btree.c:154-184,186-240`). A mutation edits the caller's in-memory node before `cow_node`; `cow_node` allocates one new block, calls `node_write` once on that edited buffer, then records the old block for retirement (`src/core/btree.c:507-522`). There is no separate unchanged-node write before the edit.

For a non-splitting mutation, insert descends once, edits the leaf, COW-writes it, and COW-writes each ancestor once (`src/core/btree.c:833-876,908-924,958-960`). Update also has a single descent; it returns without COW if the value is already equal, otherwise COW-writes the leaf and ancestors (`src/core/btree.c:1010-1046,1047-1075`). These are already one final node write per path level. Split-only sibling creation/rewrite is elsewhere (`src/core/btree.c:878-907,925-955`), consistent with the supplied zero split-hit count for these workloads.

`bfs_btree_replace_root_leaf` is the existing one-root-leaf COW primitive. For its ordinary (non-owned) form it validates height/order, preflights one deferred-retirement slot, allocates buffers, reads and validates the old root, allocates a distinct scratch block, writes the replacement once, records old-root retirement, then swaps the root and commits retirement (`src/core/btree.c:533-550,571-634`). Before the root swap, errors abort the scratch allocation; after the swap, retirement errors are returned with the new root already installed. The allocator therefore detects root change and accounts the consumed interval even on that error (`src/core/alloc.c:961-975`).

Mutation commit is part of durability/ownership, not redundant I/O: current-transaction retired nodes return through the allocator, while older roots go to the deferred sink (`src/core/btree.c:465-476`). Mounted transaction commit publishes the working roots, then reclaims pending blocks and settles reserve in a fixed point (`src/core/txn.c:219-260,263-310`). The first pending reclaim may batch sorted blocks on a height-one tree; subsequent passes keep the ordinary settlement path (`src/core/txn.c:187-217,268-304`).

### Free-space allocation

* Single-block allocation first tries `alloc_tail_from_highest`: one `search_floor(UINT32_MAX)` chooses the highest extent, followed by one update or delete (`src/core/alloc.c:455-488,542-563`). Thus this existing fast path intentionally uses highest-tail placement, not first-fit. The search and subsequent B-tree mutation each descend/read the tree.
* Other requests scan first-fit from `roving`, with an optional wrap scan (`src/core/alloc.c:565-600`). For a partial selected extent on a height-one tree, the retained path re-scans/validates the leaf into temporary key/length arrays and uses the ordinary root-leaf replacement API (`src/core/alloc.c:618-625,924-978`). The scan that selects an extent stops when it finds the candidate; the collector then scans to validate the full leaf (`src/core/alloc.c:433-450,940-960`). A full `bfs_btree_scan` processes the first leaf, then re-descends from root to find a successor (`src/core/btree.c:1169-1218,1224-1317`); on a one-leaf tree that successor probe is still another root read before scan completion. Root replacement reads the old root again. These are distinct read/traversal costs; CRC-cache hits do not turn them into a single B-tree operation.
* Exact fits are delete-only. Deeper-tree partial requests delete the selected extent and insert its remainder, so that path has two mutations; a failed remainder insert attempts to restore the old extent (`src/core/alloc.c:628-655`). This is the explicit fallback boundary documented for the first-fit root-leaf change (`docs/plans/bfs-free-tree-multiedit-v1.md:247-263`).

### Free-space return and coalescing

`bfs_freespace_free` first validates reserve/emergency-pool separation and checks that the range is absent from the free tree. For count 1 on a valid height-one tree, the absence check now uses a floor result and avoids the additional successor scan (`src/core/alloc.c:740-765`). It then separately searches the predecessor at `start-1` and the exact right key at `end` to determine adjacency (`src/core/alloc.c:802-835`). On a height-one tree, each successful `search_floor`/`search` reads the root; so an ordinary nonzero-start single-block return can perform the absence floor, left floor, and right search before mutation. This audit did not count runtime instances.

The current mutation shape depends on adjacency (`src/core/alloc.c:844-875`): two-sided merge is delete-right then update-left; left-only is one update; right-only is delete-right then insert at the lower start; no neighbor is one insert. The two-edit branches explicitly try to restore the deleted right extent if the second operation fails. Each nonempty height-one delete/update/insert COWs its root once; deleting the last key retires the root without a replacement write (`src/core/btree.c:1516-1529`). Consequently, “two-edit coalescence = 0” in the supplied profile rules out hits to that instrumented branch for those samples; it does not show which one-edit branches or extent-validation paths ran.

Sorted post-publication return is separate: on a height-one tree it scans/collects the existing leaf, merges sorted blocks, and replaces the root leaf once; deeper/full/unsupported cases fall back to range frees (`src/core/alloc.c:1073-1139`; caller in `src/core/txn.c:187-217`). This path may contribute Free-Tree writes outside the allocation body. `node_write` attributes its write to allocation, reserve refill/return, post-publication reclaim, or other phase (`src/core/btree.c:210-230`); total write counts alone do not isolate those phases.

## Existing test coverage and gaps

* `tests/test_alloc_root_shift.c:test_first_fit_run_carve_emits_one_root_leaf_write` asserts first-fit placement, one root write, accounting, roving, and reserve stability (214-231). `test_roving_wrap_skips_short_first_fit_extent` covers wrap and extent preservation (275-298); `test_exact_fit_and_single_block_keep_legacy_selection` and `test_deeper_free_tree_keeps_legacy_mutation_path` cover the current fallback boundaries (300-369).
* The same file covers pre-swap read cuts and immutable allocator state (`test_read_failure_does_not_mutate_allocator_state`, `test_read_failure_cuts_cover_every_pre_swap_read`, 371-444), root-leaf write failure plus retry (`test_partial_leaf_write_failure_is_atomic_and_retryable`, 446-493), pending-retirement headroom (`test_pending_headroom_again_precedes_root_swap`, 495-523), current/older-root retirement (`test_current_and_older_root_retirement_ownership`, 525-569), scratch exhaustion (571-597), and a CRC-correct overlapping extent rejected before write (599-665). Mounted sticky retirement errors, read-only rejection, and append/sync/readonly-remount/fsck are covered at 730-940.
* `tests/test_btree.c` separately covers old-root COW preservation (577-618), root-leaf replacement success/order/write-failure/deeper-tree rejection (1361-1444), plus delete and search-floor semantics. `tests/test_btree_buffers.c` covers cached-tree/split/delete-merge buffer lifecycle and injected failures (328-525).
* Free-return coverage includes `tests/test_alloc.c:test_merge_right` (92-117), but it asserts only that freeing three adjacent allocations succeeds; it does not assert which adjacency branch ran or its node-write count. `test_double_free_preserves_accounting` checks duplicate rejection (494-510). The checked-in active allocator tests inspected do not isolate a two-sided `bfs_freespace_free` mutation and fail its second edit to verify delete rollback, nor isolate right-only second-edit rollback. Separately, the frozen private schema-13 fixtures in `build/split-coalesce-attribution-fixtures/` cover first/second-edit and singleton rollback. Those private diagnostic fixtures are not a dedicated active allocator test for the coalescence branches.
* `tests/test_alloc.c:test_sorted_batch_reclaim_single_leaf` checks a one-root-leaf merged result, holes, duplicates and unchanged total/root on rejection (522-564); `test_sorted_batch_reclaim_full_leaf_falls_back` checks unsupported/full-leaf fallback (566-595). `tests/test_alloc_metadata_reuse.c` covers stash/pop, one-root-read stock validation, reserve floor, deeper-tree fallback, mounted write cuts/remount, and snapshot preservation (`335-407,970-998,1064-1302`). `tests/test_txn_sealed_preflight.c:test_snapshot_contexts_decline_without_writes` and shape/stock preflight cases cover restrictions on the separate sealed path (`418-556`).
* Low-space tests include exact reserve-floor and scratch-exhaustion checks above, plus pending-headroom rejection. The older `tests/test_alloc.c:test_out_of_space` has a weak oracle: it asserts `count >= 0` but does not require any successful allocations or explicitly check the terminating failure (`466-492`).

## Diagnostic limits and decision state

Current `perf_probe` SSOT has aggregate `bio_read_calls`, tree/phase node-write counters, CRC calls/samples, B-tree-TU malloc/free counters, and interface/freespace calls (`src/amiga/perf_probe.h:35-114`). It does not expose Free-Tree read counts by operation/phase, root-search/scan counts, entries visited, or calls to individual B-tree primitives. Moreover, the B-tree malloc wrapper is local to `btree.c` (`src/core/btree.c:33`): it does not include allocator scratch arrays (`src/core/alloc.c:933,1115,1469`) or transaction reclaim scratch (`src/core/txn.c:193`). Therefore historical “B-tree heap intervals are small” data is not a measurement of those allocator/transaction temporary allocations.

The useful remaining evidence gap is attribution of the already-observed calls: which mutation branch and height ran, how many root/ancestor reads and scan entries it traversed, and how much scratch memory each path allocates. One existing tagging boundary matters: `BFS_PERF_FREE_TREE_PHASE_ALLOCATION_BODY` is entered only after the first-fit selection scan (`src/core/alloc.c:565-600,613-616`). Reusing that phase for selection/read-cost attribution would leave selection work classified as `OTHER`; an operation scope would need to include selection while preserving nested reserve-refill provenance. Additional per-call/hot-loop instrumentation has overhead that is not quantified by this source audit and must not be treated as normal-handler performance evidence.

The first-fit partial root-leaf allocation is documented as implemented and locally qualified, but explicitly not general multi-edit or overall acceptance (`docs/plans/bfs-free-tree-multiedit-v1.md:247-292`). The optional repeated-tail and single-extent metadata-withdrawal prototypes were safety-qualified and rejected for normal performance regressions; their production changes were withdrawn (`docs/plans/bfs-metadata-withdrawal-batch-v1.md:1-12`). The overall ≤5× PFS3 target remains unmet; no latency forecast follows from this inventory.
